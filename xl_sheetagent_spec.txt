XLGEN — xl_sheetagent Implementation Brief v3.2
Claude Code Planning Document | xlgen_v3 Repository
================================================================

0. WHAT THIS IS
================================================================

Implementation spec for xl_sheetagent (Stage 4 in XLGEN pipeline).
Takes structural tables from xl_table, adds titles, headers, notes,
section grouping, table categorization, and sheet-level semantic
organisation.

Does NOT: re-parse structure, modify xl_table boundaries, implement
xl_kg/xl_ontology/xl_ask, or build a generalized agent framework.

Greenfield module inside an evolving monorepo. Upstream schemas are
fluid — compatibility adapter required.

================================================================
1. TOP-LEVEL RULES
================================================================

DO NOT BUILD AN AGENT FRAMEWORK.

Three typed modules, not agents:
  TableEnricher    = bounded table-local interpreter (has LLM)
  SheetCoordinator = deterministic rule engine (ZERO LLM in V1)
  GrammarBuilder   = offline batch prior-builder (V1C only)

Every decision follows: observe → score → threshold → accept/escalate

Five scoring functions in scoring.py are the algorithmic core.
Modules are thin wrappers that call scorers and apply config thresholds.

No message queues, event buses, or agent memory. Typed function calls
and return values only.

================================================================
2. PIPELINE POSITION
================================================================

  Stage 0: xl_init       → cleaned workbook, shapes, metadata
  Stage 1: xl_parse      → candidate_rows.jsonl + sibling parse artifacts (flat)
  Stage 2: xl_table      → structural tables (TableObject / StructuralTables)
  Stage 3: xl_image      → bbox PNGs, feature JSONs (OPTIONAL for V1A/V1B)
  Stage 4: xl_sheetagent → EnrichedTableObject, SheetObjectTree  ← THIS
  Stage 5+: xl_ontology, xl_ask (future, out of scope)

  Dependency rule (monorepo):
    xl_sheetagent REQUIRES xl_init + xl_parse + xl_table outputs for the same run_id.
    xl_image is NOT a prerequisite for V1A/V1B; use when V1C needs visual tiles /
    formatting renders. Stage numbers above are ordinal labels, not strict execution
    order for optional stages.

3. UPSTREAM COMPATIBILITY
================================================================

upstream_compat.py normalises all upstream inputs. Single place for
field defaults, fallback logic, and version branching.

Field classifications:
  REQUIRED — fail fast if missing
  EXPECTED — apply fallback default, log warning
  OPTIONAL — skip gracefully

Key fields (implement these fallbacks):

  REPO FILENAME MAP (logical / brief name → actual file in xlgen_v3):
    selected_sheets.json      → approved_sheets.json (init_output/)
    shape_objects.json        → shapes_manifest.jsonl (init_output/; optional)
    sheet_metadata (single)   → sheet_metadata/ directory (per-sheet JSON under init_output/)
    table_index.json          → structural_tables.json (+ tables_per_sheet.json; table_output/)
    GridTableObject           → TableObject inside StructuralTables / SheetObjectTree (xl_table)

  candidate_rows.jsonl:
    candidate_id              REQUIRED    fail fast
    sheet_name                REQUIRED    fail fast
    bbox {r0,c0,r1,c1}       REQUIRED    fail fast  (0-indexed inclusive corners)
    density                   REQUIRED    fail fast
    provenance                REQUIRED after normalise:
                                xl_parse may emit provenance as a STRING; map to object
                                { "method": <string>, "ancestor_ids": [] } for downstream.
                                If object with .method missing, EXPECTED → derive or "unknown"
    provenance.ancestor_ids   EXPECTED    → empty list
    header_row_indices        EXPECTED    → empty list, force Tier B
    header_confidence         EXPECTED    → 0.0, force Tier B
    separator_scores          EXPECTED    → empty list
    col_separator_scores      OPTIONAL    → empty list
    qc_flags                  EXPECTED    → empty list
    structural_type           EXPECTED    → 'table'
    bbox_stats                EXPECTED    → empty object
    cell_features             OPTIONAL    → empty object

  TableObject / StructuralTables (from structural_tables.json):
    table_id                  REQUIRED    fail fast
    sheet_name, bbox          REQUIRED    fail fast
    body_bbox                 EXPECTED    → full bbox
    header_row_indices_guess  EXPECTED    → empty list
    row_header_column_guess   OPTIONAL    → null
    confidence                EXPECTED    → 0.5
    split_history             EXPECTED    → {was_split: false}
    rejected_cuts             OPTIONAL    → empty list
    parse_metadata            OPTIONAL    → empty object
    structural_tables.json    REQUIRED    (spatial analysis; primary table bundle)
    dependency_groups.json    OPTIONAL    (skip if absent — not always present in repo)

  xl_init:
    cleaned_workbook.xlsx     REQUIRED    fail fast (typically init_output/cleaned_workbook.xlsx)
    approved_sheets.json      REQUIRED    fail fast (not selected_sheets.json)
    shapes_manifest.jsonl     EXPECTED    → empty (skip shape matching if absent)
    sheet_metadata/           EXPECTED    → derive from workbook if folder missing
    guide_sheet_candidates    OPTIONAL    → LLM scan only (V1C)

  xl_parse (parse_output/ root):
    rejected_blocks.jsonl     EXPECTED    → empty list of lines if absent
                                Each line: sheet_name, bbox_r1..bbox_c2, rejection_stage,
                                reason_codes, provenance, n_cells_on, density.
                                SheetCoordinator consumes this FIRST (before other signal
                                resolution) for sheet-level context: header bands, edition
                                titles, and regions that did not become final candidates.

run_manifest.json must include:
  upstream_schema_versions: {xl_parse: "detected_vN", xl_table: "detected_vN"}

4. SCORING FUNCTIONS — THE CORE
================================================================

All in scoring.py. Deterministic. No LLM. Independently testable.
≥10 test cases each. Scoring functions must be implemented and tested
first, but thin module wrappers may be created in parallel.

4.1 title_attachment_score → float 0-1

  Inputs: spatial_distance, text_match, grammar_match, shape_match,
          is_merged_full_width, is_bold, has_formula
  Logic:
    spatial_distance: exponential decay (0→1.0, 1→0.85, 2→0.65, 3→0.40)
    is_merged_full_width: ×1.15 | is_bold: ×1.05
    has_formula: ×0.1 (strong rejection)
    grammar_match: +0.15 | shape_match: +0.10 | text_match: +0.10
    Clamp [0,1]
  Used by: TableEnricher Steps 1 and 3

4.2 section_ownership_score → float 0-1

  Inputs: band_proximity, formatting_match, grammar_confidence,
          table_count_under, is_full_width, has_merge_span
  Logic:
    band_proximity: exponential decay (primary)
    table_count_under == 0: → 0.05 (noise)
    is_full_width: ×1.20 | has_merge_span: ×1.10
    formatting_match: +0.15 | grammar_confidence: +0.20
    Clamp [0,1]
  Used by: SheetCoordinator (V1B+)

4.3 header_inheritance_score → float 0-1

  Inputs: column_range_overlap, row_proximity, formatting_similarity,
          same_section, source_has_headers
  Logic:
    source_has_headers == false: → 0.0 (gate)
    column_range_overlap < 0.50: → 0.05
    column_range_overlap: linear (primary)
    row_proximity: exponential decay (0→1.0, 3→0.70, >10→0.10)
    formatting_similarity: +0.10 | same_section: +0.10
    Clamp [0,1]
  Used by: SheetCoordinator signal resolution

4.4 note_scope_score → (scope: str, confidence: float)

  Inputs: spatial_distance, text_keywords, table_count_nearby,
          is_after_last_table
  Logic:
    distance≤1 and count==1 → ('single_table', 0.90)
    after_last and 'all' in keywords → ('sheet', 0.85)
    after_last no keywords → ('sheet', 0.60)
    count>1 and distance≤3 → ('section', 0.70)
    else → ('ambiguous', 0.40)
  Used by: TableEnricher Step 1 and SheetCoordinator

4.5 column_split_score → float 0-1

  Inputs: col_separator_score, formatting_discontinuity,
          header_group_break, tile_evidence, bbox_width
  Logic:
    col_separator_score: linear (primary)
    formatting_discontinuity: +0.15 | header_group_break: ×1.25
    tile_evidence: +0.20 (V1C only, 0 otherwise)
    bbox_width < 6: ×0.5 (penalty)
    Clamp [0,1]
  Used by: TableEnricher Step 2

================================================================
5. AMBIGUITY TAXONOMY
================================================================

Every confidence object and signal carries ambiguity_class:

  STRUCTURAL   — missing structural element (header, boundary)
                  threshold: 0.80, fallback: Tier B LLM then flag
  SEMANTIC     — meaning/grouping unclear despite complete structure
                  threshold: 0.65, fallback: best-guess, never block
  PRESENTATION — formatting-implied grouping, uncertain if logical
                  threshold: 0.70, fallback: score + accept or flag

6. MODULE CONTRACTS
================================================================

6.1 TableEnricher (modules/table_enricher.py)

  Input:  TableObject (+ upstream compat view) + local context + GrammarSnapshot (V1C+)
  Output: EnrichedTableObject + signals[]

  Steps:
    0. Pre-filter: content_bbox + context_block routing (V1A)
    1. Boundary validation (title_attachment_score, note_scope_score)
    2. Split detection (column_split_score, provenance grep)
    3. Header resolution (scorer → shape check → rejected_blocks.jsonl regions → LLM)
         rejected_blocks.jsonl: same parse_output/ file SheetCoordinator uses; filter
         rows by sheet_name and spatial overlap / proximity to this table for header
         and title cues from non-final blocks.
    4. LLM interpretation + table_category + rag_fields (V1C ONLY)

  STEP 0 — PRE-FILTER (two checks before Steps 1-3):

  (A) content_bbox computation:
    Compute tightest non-empty sub-region within the table bbox (TableObject).
    Example: bbox B58:L64 but B58:F64 is empty → content_bbox = G58:L64.
    Also compute empty_zones[] classified by position:
      leading_rows, trailing_rows, leading_cols, trailing_cols, internal
    Rules:
      Leading/trailing empty zones → trimmable, exclude from LLM payloads
      Internal empty zones → NOT trimmable, flag as split evidence for Step 2
    payload_builder always uses content_bbox, never raw bbox.
    Original table bbox is never modified.

  (B) context_block routing:
    If ALL true: formula_ratio < 0.05, row_count ≤ 5, adjacent to
    (within 2 rows of) another table (TableObject) →
    Downgrade to context_block. Do NOT run Steps 1-4.
    Emit orphan_rows signal with content_type="context_block".
    SheetCoordinator attaches it as title/header/note to adjacent table.
    Prevents junk table nodes in tree and KG.

  LLM: allowed, bounded, via payload_builder only.
  Shapes: checked in Step 3 Level 2 (V1A+, before LLM).

  Splits produce semantic_partitions (advisory only):
    partition_type: "semantic_overlay"
    authoritative: false
    derived_from_table_id, sub_bbox, suggested_title, confidence

  In V1B+, confirmed partitions (confidence ≥ table_finalization) become
  CHILD NODES (node_type: "table_partition") in SheetObjectTree.
  Critical for model tree: Section → Table → [Cost, Population, Utilities]

  In V1C, Step 4 runs PER PARTITION, not per parent table.
  Each partition gets its own summary, section_path, table_category.

  SheetObjectTree node types:
    "section"          — section/subsection band
    "table"            — top-level TableObject / enriched table
    "table_partition"  — semantic sub-table within parent
    "context_block"    — zero-formula block attached to adjacent table
    "note"             — attached note/footnote
    "shape"            — attached shape (see shape_subtype below)

6.2 SheetCoordinator (modules/sheet_coordinator.py)

  Input:  all EnrichedTableObjects + signals + shapes + GrammarSnapshot
          + parse_output/rejected_blocks.jsonl (loaded at start of coordination)
  Output: SheetObjectTree + relationship edges

  ZERO LLM CALLS IN V1. Test-enforced.

  Load order (V1B+):
    1. Parse rejected_blocks.jsonl into an index keyed by sheet_name (and spatial order).
    2. Use this index FIRST to inform section bands, edition titles, and non-candidate
       regions before resolving TableEnricher signals.
    3. Then apply scoring functions below.

  Resolves signals deterministically using scoring functions:
    orphan_rows → match via title_attachment_score
    header_unresolved → resolve via header_inheritance_score
    shared_note → resolve via note_scope_score
    section_ambiguity → check adjacent assignments + skeleton
    context_block → attach to nearest real table as title/note

  V1B section grouping is CONSERVATIVE. Under-assign, don't over-assign.

6.3 GrammarBuilder (modules/grammar_builder.py) — V1C ONLY

  Input:  approved_sheets.json (or equivalent list), guide_sheet_candidates, sample cell_features
  Output: GrammarSnapshot.json (frozen, immutable after Phase 1)

  Guide sheet fallback:
    candidates exist conf>0.7 → use as primary
    candidates exist all<0.7  → LLM sheet-name scan primary
    candidates absent         → observed-only mode
    detected but noisy        → cap declared rules at 0.6

  Sampling: 2-4 sheets by table count, formatting diversity, bbox count.
  Promotion: observed→confirmed needs ≥3 occurrences on ≥2 sheets.
  GrammarSnapshot is READ-ONLY during Phase 2. Static JSON, not memory.

7. TABLE CATEGORY — DOWNSTREAM-CRITICAL FIELD
================================================================

Every EnrichedTableObject (and every partition) must carry:

  table_category: Literal[
    'input',       # user-editable parameters
    'assumption',  # fixed assumptions (discount rate, horizon)
    'calc',        # intermediate calculation tables
    'output',      # results tables (ICER, NMB, total costs)
    'reference',   # reference data (unit costs, mortality rates)
    'note',        # explanatory text blocks
    'summary',     # model summary / dashboard tables
    'unknown'      # could not classify
  ]
  table_category_confidence: float
  table_category_reasoning: str

This is the single most important downstream field for xl_ontology
and xl_ask. Without it, downstream must infer table role from prose.

V1A — deterministic partial inference (no LLM):
  formula_ratio > 0.70                    → 'calc' (conf 0.60)
  formula_ratio < 0.05 and rows ≤ 5      → 'note' (conf 0.55)
  formula_ratio < 0.10 and all text       → 'reference' (conf 0.50)
  context_block = true                    → 'note' (conf 0.70)
  otherwise                               → 'unknown' (conf 0.0)

  Monorepo note — formula_ratio:
    xl_table opens the workbook data_only=True, so formula_ratio stored on upstream
    TableObject may be 0.0. For sheetagent, recompute formula_ratio (or equivalent)
    by opening init_output/cleaned_workbook.xlsx with data_only=False for the table
    bbox, OR treat missing ratios as EXPECTED and fall through to 'unknown' / LLM
    (V1C). Document which approach is implemented in upstream_compat.

V1C — LLM-confirmed upgrade via Step 4:
  summary_context prompt includes: "Classify this table as one of:
  input, assumption, calc, output, reference, note, summary."
  LLM result overwrites V1A inference with higher confidence.

8. SHAPE HANDLING — SUBTYPE + LINKING
================================================================

Shape nodes in SheetObjectTree must carry:

  shape_subtype: "textbox" | "chart" | "button" | "image" | "form_control"
  linked_table_id: str or null   (for charts: which table it visualizes)
  text_content: str or null

shape_subtype comes from shapes_manifest.jsonl (init_output/) — map upstream
shape_type / type fields to shape_subtype.
linked_table_id: for charts, check if chart source range overlaps any
table bbox. If overlap > 50% → link. Implemented in V1B.

This matters for downstream knowledge graphs: "chart X visualizes table Y" is a graph edge.

9. SIGNALS (four types)
================================================================

  orphan_rows          STRUCTURAL    TableEnricher → Coordinator
  header_unresolved    STRUCTURAL    TableEnricher → Coordinator
  shared_note          SEMANTIC      TableEnricher → Coordinator
  section_ambiguity    PRES/SEM      TableEnricher → Coordinator

  @dataclass
  class TableSignal:
      signal_type: Literal[...]
      ambiguity_class: Literal['STRUCTURAL','SEMANTIC','PRESENTATION']
      source_table_id: str
      confidence: float
      evidence_summary: dict

12. PHASE PLAN
================================================================

After each phase: run tests, summarize, show examples, STOP for review.

Acceptance metrics are TARGET BENCHMARKS, not hard pass/fail gates.

--------------------------------------------
V1A — SCORING + FLAT ENRICHMENT
--------------------------------------------

No grammar. No imaging. No section skeleton. No tree rendering.

Implementation order:
  1. Package scaffold + sheetagent_config.yaml + config.py
  2. Schemas (EnrichedTableObject with content_bbox, empty_zones,
     table_category, is_context_block; TableSignal; RunManifest)
  3. upstream_compat.py + tests
  4. scoring.py (all 5 functions) + test_scoring.py (≥10 cases each)
  5. Synthetic fixtures (9 .xlsx — see below)
  6. provenance_tools.py + payload_builder.py
     payload_builder always uses content_bbox, never raw bbox.
     Only implement modes needed for V1A:
     top_rows_text_only, top_rows_with_formulas,
     bottom_rows_text_only, footnote_context, table_pair_boundary_view
  7. Step 0 (content_bbox + context_block routing)
     + Steps 1-3 + table_enricher.py
  8. table_category partial inference (deterministic, no LLM)
  9. exporter.py + minimal SheetCoordinator placeholder
  10. run_sheetagent.py (CLI entry)
  11. Integration tests. RUN ALL. Summarize. STOP.

Target benchmarks:
  ≥90% title rate, ≥80% column header rate on fixtures
  ≥1 header inheritance, ≥1 shape-based title
  ≥1 context_block correctly downgraded
  table_category assigned (even if 'unknown') on every table
  content_bbox computed for every table
  debug_log.jsonl records every scoring call

--------------------------------------------
V1B — DETERMINISTIC SHEETCOORDINATOR
--------------------------------------------

No grammar. No imaging. Section grouping from cell_features JSON only.
V1B is the first true semantic grouping milestone — expect uncertainty
on real BIMs.

Adds:
  Full SheetCoordinator (ZERO LLM — test-enforced)
  Section skeleton from cell_features.fill_color_groups (no image render)
  If xl_parse exports font size/border in cell_features, use them too.
  Orphan pool, shared note pool, header inheritance
  context_block attachment to adjacent tables
  section_ambiguity signal
  SheetObjectTree with all node types (section, table, table_partition,
    context_block, note, shape with shape_subtype + linked_table_id)
  Relationship edges + view bundle
  Chart-to-table linking via source range overlap

Section grouping is CONSERVATIVE. Under-assign, don't over-assign.

Only implement payload modes needed for V1B:
  formatting_signature_only, neighbor_text_only

Target benchmarks:
  ≥70% section rate on real BIMs
  ≥1 parent section with 3+ tables
  SheetCoordinator: 0 LLM calls (verified in debug_log)
  context_blocks attached as tree children, not standalone nodes

--------------------------------------------
V1C — GRAMMAR + IMAGING + STEP 4
--------------------------------------------

Adds:
  GrammarBuilder + GrammarSnapshot
  xl_image: sheet_formatting_render + local_tile_render (best-effort)
  Visual section skeleton in SheetCoordinator
  Step 4 LLM interpretation in TableEnricher
  Grammar-aware scoring upgrades

  Step 4 runs PER PARTITION, not per parent table.
  Each partition gets its own summary, section_path, table_category.

  table_category LLM confirmation — overwrites V1A partial inference.
  rag_fields generated for every table and partition.

  Formula-aware payload mode:
    For tables with formula_ratio > 0.5, summary_context payload
    must include first 2 rows of A1-style formulas so LLM understands
    calculation structure. Do not strip formulas from calc tables.

  Text-dominant sheet mode:
    If sheet has > 70% text cells across all tables → treat as
    text-dominant. Read in chunks, classify as intro/assumptions/
    references/repeated. Produce sheet-level text summary rather
    than forcing per-table enrichment on prose content.
    Flag sheet as text_dominant in sheet metadata.

Only implement remaining payload modes:
  header_plus_sample_body, local_title_context, summary_context
  summary_context: partition-aware + formula-aware variants.

Image/COM failure: log and continue, cap scores, no crash.

Target benchmarks:
  ≥1 guide sheet detected, grammar confirmed on ≥2 sheets
  Section rate improves ≥10% over V1B
  table_category LLM-confirmed on ≥80% of tables

--------------------------------------------
V1D — VIEWER + HARDENING
--------------------------------------------

Adds:

  Thin Streamlit viewer (reads artifacts only, no pipeline logic)

================================================================
15. CLAUDE CODE RULES
================================================================

  1. One phase at a time. V1A first.
  2. Scoring functions first, thin wrappers in parallel OK.
  3. No GrammarBuilder or imaging until V1C.
  4. No agent framework, message buses, or event systems.
  5. modules/ folder, not agents/.
  6. SheetCoordinator: ZERO LLM in V1. Test-enforce this.
  7. step_log[] on EnrichedTableObject for table events.
     debug_log.jsonl for sheet/run scope events.
  8. All thresholds from config, never hardcoded.
  9. Only implement payload modes needed for current phase.
  10. Every scoring call logged in debug_log.jsonl.
  11. Every LLM call via payload_builder.
  12. Every confidence object carries ambiguity_class.
  13. Step 0: compute content_bbox (tightest non-empty sub-region).
      payload_builder uses content_bbox, never raw bbox.
      Leading/trailing empty zones are trimmable.
      Internal empty zones are split evidence for Step 2.
  14. Step 0: context_block routing. Zero-formula ≤5-row tables
      adjacent to real tables → downgrade, emit orphan signal.
  15. table_category MANDATORY on every EnrichedTableObject.
      V1A: deterministic from formula_ratio.
      V1C: LLM-confirmed with confidence + reasoning.
  16. Semantic partitions: partition_type="semantic_overlay",
      authoritative=false. In V1B+ become child nodes
      (node_type="table_partition") in SheetObjectTree.
  17. In V1C Step 4, run LLM per partition. Each gets own summary,
      section_path, table_category, rag_fields.
  18. Shape nodes carry shape_subtype + optional linked_table_id.
  19. rag_fields (V1C): embedding_description, key_entities,
      table_category, section_path. Stable retrieval schema.
  20. Formula-aware payload for calc tables (formula_ratio > 0.5):
      include first 2 rows of A1-style formulas in summary_context.
  21. Text-dominant sheets (>70% text): flag, read in chunks,
      classify as intro/assumptions/references. Do not force
      per-table enrichment on prose content.
  22. On failure (image, LLM, upstream): log and continue, cap
      scores, never crash.
  23. After each phase: run tests, summarize, show examples, STOP.
  24. Use core/paths.py for all output roots; add sheetagent_output helper alongside
      existing stage paths.
  25. xl_parse MUST write all run artifacts flat under parse_output/ only (§2.1); no
      timestamped export subfolders.
  26. upstream_compat MUST implement the REPO FILENAME MAP in §3 (approved_sheets,
      shapes_manifest, structural_tables, rejected_blocks.jsonl, provenance string).
  27. LLM integration MUST follow §10.1 (OpenAI + gpt-3.5-style config, env bootstrap).
  28. SheetCoordinator MUST load rejected_blocks.jsonl before other spatial resolution (§6.2).
  29. Repo policy: do not introduce the legacy xl_kg substring in xl_sheetagent .py
      sources (monorepo test enforces this for stage packages).

End of spec.
