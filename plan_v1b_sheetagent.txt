xl_sheetagent V1B Implementation Plan
======================================

0. CONTEXT
======================================

V1B is the first true semantic grouping milestone. It transitions the
SheetCoordinator from a pass-through placeholder to a full deterministic
signal resolver, builds the SheetObjectTree with all node types, and
adds relationship edges.

V1B adds NO grammar (V1C), NO imaging (V1C), NO LLM calls (ZERO LLM
in SheetCoordinator — test-enforced). Section grouping uses cell_features
from candidate_rows.jsonl (fill_color_groups, font size, borders) only.

Conservative section assignment: under-assign, don't over-assign.

V1A delivered: 5 scoring functions (all tested), content_bbox + context_block
pre-filtering, Steps 1-3 enrichment, table_category inference, signals
emitted but unresolved, exporter, CLI.

V1B resolves those signals and builds the tree.


======================================
1. WHAT V1B ADDS (from spec S12)
======================================

  Full SheetCoordinator (ZERO LLM — test-enforced)
  Section skeleton from cell_features.fill_color_groups (no image render)
  If xl_parse exports font size/border in cell_features, use them too
  Orphan pool, shared note pool, header inheritance
  context_block attachment to adjacent tables
  section_ambiguity signal
  SheetObjectTree with all node types:
    section, table, table_partition, context_block, note, shape
  Relationship edges + view bundle
  Chart-to-table linking via source range overlap
  EnrichedTableObject gains: section_path, section_assignment_confidence,
    parent_section_id
  New payload modes: formatting_signature_only, neighbor_text_only

Target benchmarks:
  >= 70% section rate on real BIMs
  >= 1 parent section with 3+ tables
  SheetCoordinator: 0 LLM calls (verified in debug_log)
  context_blocks attached as tree children, not standalone nodes

Step 3: Section skeleton detector
--------------------------------------------

The SheetCoordinator needs to detect section bands BEFORE resolving signals.
This is the core V1B algorithm — extract sections from formatting cues in
candidate_rows and from rejected_blocks.

NEW FILE:
  xl_sheetagent/modules/section_detector.py

  def detect_sections(
      sheet_name: str,
      candidate_rows: List[dict],
      rejected_blocks: List[dict],
      enriched_tables: List[EnrichedTableObject],
      ws,
      cfg,
  ) -> (List[SectionBand], List[dict]):
      """Detect section bands from formatting cues.

      Sources (in priority order):
        1. rejected_blocks.jsonl: merged-cell rows, wide text-only rows
           with fill color or bold formatting (spec S6.2: load first)
        2. candidate_rows.cell_features: fill_color_groups, font size, borders
        3. Workbook scan: merged cells spanning full table width with
           fill color and bold text

      Returns (section_bands, debug_events).
      """

  @dataclass SectionBand:
    band_id: str
    sheet_name: str
    r_top: int
    c_left: int
    r_bot: int
    c_right: int
    title: str
    is_full_width: bool
    has_merge_span: bool
    formatting_signature: dict   # {fill_color, font_size, is_bold}
    confidence: float

  Algorithm:
    1. Index rejected_blocks by sheet_name (spec S6.2 load order).
    2. For each rejected block on the sheet: check if it looks like a
       section band (is_full_width, has_merge, has_fill, text content,
       1-2 rows tall). Score with section_ownership_score. If score >=
       section_assignment_accept -> candidate section band.
    3. Scan workbook rows above/between tables for merged-cell bands
       (openpyxl merged_cells check). Same scoring.
    4. Deduplicate overlapping bands (keep highest confidence).
    5. Sort by r_top (spatial order).

  CONSERVATIVE: Only detect bands with strong formatting signals.
  Under-assign (leave tables unassigned) rather than over-assign.

TESTS:
  xl_sheetagent/tests/test_section_assignment.py
    - Detects blue merged band from fixture_section_bands.xlsx
    - Does not hallucinate sections from plain rows
    - Deduplicates overlapping bands

Step 4: Full SheetCoordinator implementation
--------------------------------------------

MODIFIED FILE:
  xl_sheetagent/modules/sheet_coordinator.py

  Replace pass-through with full deterministic resolution.

  def coordinate_sheet(
      enriched_tables: List[EnrichedTableObject],
      signals: List[TableSignal],
      upstream: UpstreamData,
      ws_by_sheet: Dict[str, Worksheet],  # V1B needs workbook access
      cfg,
  ) -> (List[EnrichedTableObject], List[TableSignal],
        Dict[str, SheetObjectTree], Dict[str, RelationshipGraph],
        List[dict]):  # debug_events

  Implementation (per sheet):

    Phase 1: Load + index
      a. Index rejected_blocks by sheet_name (spec S6.2 — MUST be first).
      b. Call detect_sections() for section skeleton.
      c. Build orphan pool, shared note pool from signals.
      d. Index shapes by sheet_name from upstream.shapes_manifest.

    Phase 2: Signal resolution (deterministic, no LLM)
      a. orphan_rows signals:
         - If evidence_summary.content_type == "context_block":
           attach to nearest real table (gap <= context_block_adjacency_max).
         - Else: try title_attachment_score against nearby tables.
           If best score >= tier_b_accept -> assign as title.
         - Log every scoring call.

      b. header_unresolved signals:
         - For each unresolved table, find nearest table with resolved headers.
         - Score with header_inheritance_score(column_range_overlap,
           row_proximity, formatting_similarity, same_section,
           source_has_headers).
         - If score >= header_unresolved_floor -> inherit headers.
         - Update enriched table's column_headers.

      c. shared_note signals:
         - Resolve via note_scope_score to determine scope.
         - single_table -> attach as child note node.
         - sheet -> attach to sheet root.
         - section -> attach to section node.

      d. section_ambiguity:
         - If table could belong to two sections (delta < section_ambiguity_delta):
           leave unassigned. Emit section_ambiguity signal.

    Phase 3: Section assignment
      a. For each section band, find tables spatially below it and above
         the next section band (or sheet end).
      b. Score assignment with section_ownership_score.
      c. If score >= section_assignment_accept -> assign.
      d. Tables between sections: assign to above section if proximity score
         passes. Otherwise leave unassigned.
      e. Populate enriched_table.section_path, section_assignment_confidence,
         parent_section_id.

    Phase 4: Tree assembly
      a. Call sheet_assembler.build_tree() (see Step 5).
      b. Call relationship_builder.build_relationships() (see Step 6).

  ZERO LLM CALLS. Test-enforced.

  V1B signature change note:
    coordinate_sheet() gains upstream and ws_by_sheet parameters.
    __init__.py must be updated to pass these through.

TESTS:
  xl_sheetagent/tests/test_coordinator.py
    - Orphan rows resolved to nearest table
    - Header inheritance from stacked tables
    - Context blocks attached as children, not standalone
    - Section assignment with conservative threshold
    - Zero LLM calls (grep debug_log for "llm" or "openai")
    - section_ambiguity emitted when delta < threshold

--------------------------------------------
Step 5: Sheet assembler (tree builder)
--------------------------------------------

NEW FILE:
  xl_sheetagent/assembly/sheet_assembler.py

  def build_tree(
      sheet_name: str,
      enriched_tables: List[EnrichedTableObject],
      section_bands: List[SectionBand],
      signals: List[TableSignal],
      shapes: List[dict],
      cfg,
  ) -> SheetObjectTree:

  Algorithm:
    1. Create section nodes from section_bands.
    2. Create table nodes from enriched_tables (non-context-block).
    3. For confirmed semantic_partitions (confidence >= cfg.table_finalization):
       create table_partition child nodes under parent table (spec S6.1 rule 16).
    4. Create context_block nodes. Attach as children of their target table
       (determined by signal resolution in coordinator).
    5. Create note nodes from footnotes with sheet/section scope.
    6. Create shape nodes from shapes_manifest:
       - Map upstream shape_type to shape_subtype
         (textbox|chart|button|image|form_control).
       - Set linked_table_id for charts (from Step 6 linking).
       - Set text_content for textboxes.
    7. Parent-child wiring:
       - Section contains tables (from Phase 3 assignment).
       - Table contains partitions, context_blocks, notes.
       - Unassigned tables -> root level.
    8. Compute summary counts.

Step 6: Relationship builder + chart linking
--------------------------------------------

NEW FILE:
  xl_sheetagent/assembly/relationship_builder.py

  def build_relationships(
      tree: SheetObjectTree,
      shapes: List[dict],
      enriched_tables: List[EnrichedTableObject],
      cfg,
  ) -> RelationshipGraph:

  Edge types:
    "contains"         section -> table, table -> partition
    "inherits_header"  table -> source_table (from header_inheritance)
    "visualizes"       chart -> table (from source range overlap)
    "annotates"        note -> table, context_block -> table
    "groups"           section -> [tables] (from section assignment)

  Chart-to-table linking (spec S8):
    For each shape with shape_subtype=="chart":
      - Extract source_range from shapes_manifest (if available).
      - Parse source_range to bbox.
      - Check overlap with each table bbox.
      - If overlap > 50% -> create "visualizes" edge, set linked_table_id.
    If source_range is not available in shapes_manifest, skip linking.

======================================
4. KEY DESIGN DECISIONS
======================================

1. rejected_blocks index (spec S6.2):
   SheetCoordinator builds a keyed index (by sheet_name + spatial order)
   BEFORE any signal resolution. This index is shared with section_detector.
   Step 3 (headers) in V1A accessed rejected_blocks directly — in V1B the
   coordinator owns the index and Step 3 should use it via a shared data
   structure passed in. To avoid refactoring Step 3 in V1B, the coordinator
   passes the index through upstream data; Step 3 continues to work as-is
   since it already filters by sheet_name.

2. Section detection is CONSERVATIVE:
   Only detect sections from strong formatting signals (merged cells with
   fill color + bold). If a region doesn't clearly look like a section
   header, leave tables unassigned rather than guessing.

3. tree node_ids:
   Format: "{sheet_name}::sec_{idx}", "{sheet_name}::tbl_{table_id}",
   "{sheet_name}::part_{table_id}_{idx}", "{sheet_name}::ctx_{table_id}",
   "{sheet_name}::note_{idx}", "{sheet_name}::shape_{idx}".

4. Confirmed partitions become child nodes:
   SemanticPartitions with confidence >= cfg.table_finalization (0.70) are
   promoted to node_type="table_partition" in the tree. Lower-confidence
   partitions stay as advisory metadata on the parent EnrichedTableObject.

5. SheetCoordinator signature change:
   V1A: coordinate_sheet(enriched_tables, signals, cfg)
   V1B: coordinate_sheet(enriched_tables, signals, upstream, ws_by_sheet, cfg)
   Returns additional: trees, rels, debug_events.

6. Zero LLM enforcement:
   test_coordinator.py must grep all debug events for any LLM-related keys
   and assert count == 0. This is the spec's test-enforced guarantee.

======================================

All 5 scoring functions from V1A are reused. V1B is the first phase
that calls section_ownership_score and header_inheritance_score from
actual coordinator logic (they were implemented+tested in V1A but had
no caller).

  section_ownership_score  -> section_detector, coordinator Phase 3
  header_inheritance_score -> coordinator Phase 2b
  title_attachment_score   -> coordinator Phase 2a (orphan resolution)
  note_scope_score         -> coordinator Phase 2c (shared note resolution)
  column_split_score       -> unchanged from V1A (Step 2)
